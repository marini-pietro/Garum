# Contributing to Garum

Thank you for your interest in contributing to Garum! The following guidelines will help you get started quickly and make the review process smooth for everyone.

## How to Contribute

### Reporting Bugs

1. Search the [existing issues](../../issues) to make sure the bug has not already been reported.
2. If no existing issue matches, open a new one and include:
   - A clear and descriptive title.
   - Steps to reproduce the problem.
   - The expected behaviour and what you observed instead.
   - Your operating system and Garum version.

### Suggesting Features

1. Search the [existing issues](../../issues) to avoid duplicates.
2. Open a new issue labelled **enhancement** and describe:
   - The problem you are trying to solve.
   - Your proposed solution or feature.
   - Any alternatives you have considered.

### Submitting a Pull Request

1. Fork the repository and create your branch from `main`:
   ```bash
   git checkout -b feature/my-feature
   ```
2. Make your changes, keeping commits focused and with descriptive messages.
3. Ensure your code follows the existing style of the project.
4. Open a pull request against `main` and fill in the template with a clear description of your changes and the motivation behind them.

## Code of Conduct

Please be respectful and considerate in all interactions. Constructive feedback and collaborative discussion are always welcome.
